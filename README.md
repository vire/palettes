# data-viz-palettes

100 categorical **5-colour palettes** sourced from [coolors.co](https://coolors.co/generate)
and scored for **data-visualisation suitability** — distinctness, harmony, lightness/chroma
balance, and colourblind-safety.

- **100** palettes total
- **24** pass the data-viz suitability floors (`suitable: true`)
- **13** are colourblind-safe under simulated deuteranopia *and* protanopia
- Ranked best-first by a composite score

> Provenance: palettes were generated by driving `coolors.co/generate` and reading each
> palette's five hex codes from coolors' own URL, then scored offline. coolors' generator is
> random, so most raw palettes are *not* ideal for categorical encoding (near-duplicate or
> extreme colours) — the `suitable` flag and ranking exist precisely to surface the good ones.

## Files

| File | What it is |
|---|---|
| `data-viz-palettes.json` | The dataset — 100 palettes with colours, names, and full scores. |
| `index.html` | Self-contained browser (data embedded; opens straight from `file://`). |
| `build-palettes-preview.mjs` | Regenerates the preview HTML from the JSON. |

## Use it

Open the preview to browse, filter (All / Suitable / CVD-safe), sort, and test palettes
against dark / light / grey backgrounds — each card includes a mini bar + scatter chart
built from the palette's own colours so you can judge it as real data viz:

```bash
npm run preview      # macOS: opens index.html
# or just open index.html in any browser
```

Consume the data programmatically:

```js
import palettes from './data-viz-palettes.json' with { type: 'json' };

const best = palettes.palettes.filter(p => p.suitable);          // the 24 keepers
const safe = palettes.palettes.filter(p => p.scores.cvd.safe);   // colourblind-safe
const top  = palettes.palettes[0].colors;                        // highest composite
```

## Regenerate the preview

The preview is built from the JSON (data embedded inline, so no fetch/CORS issues):

```bash
npm run build        # node build-palettes-preview.mjs  (bun run build also works)
```

```jsonc
      "suitable": true,

        "contrastVsBlack": 2.1,

          "deuteranopiaMinDeltaE": 8.1,

        }
      }

```

## How the scores work

| Score | Meaning |
|---|---|
| **distinctness** | min pairwise [CIEDE2000](https://en.wikipedia.org/wiki/Color_difference#CIEDE2000) across the 5 colours — higher means categories are easier to tell apart. The dominant data-viz criterion. |
| **harmony** | hue evenness around the colour wheel minus clashy near-hue/far-lightness pairs (a "sentiment" proxy). |
| **lightnessBalance** | penalises large CIELAB L\* spread — categorical palettes want similar salience. |
| **chromaBalance** | vivid enough to distinguish, not garish, with consistent chroma. |
| **cvd** | deuteranopia & protanopia simulated with the [Machado 2009](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/CVD_Simulation.html) matrices; `safe` when the simulated min ΔE stays ≥ 13 under both. |
| **composite** | weighted blend: 0.40 distinctness · 0.20 harmony · 0.15 lightness · 0.15 chroma · 0.10 cvd. |

A palette is flagged `suitable` when `minDeltaE2000 ≥ 12` and every colour's L\* is within `[15, 92]`
(no near-duplicate colours, nothing washing out to near-white or near-black).
